# Studio Da’lo — portfolio and editor upgrade

This run implements the non-Drive parts of the owner's upgrade brief. The original earthy palette, header, hero reveal, readable type and tightened Approach spacing are retained.

## Using the new features

- Click a project cover or gallery image to open the connected viewer. Use arrows, keyboard arrows, thumbnails or a horizontal swipe. The cover appears once and every distinct gallery asset remains in Sanity order. Images fit uncropped. Film slides retain native controls.
- Playback is manual by default. Optional slideshow playback advances every five seconds, pauses on film slides or when the page is hidden, and is disabled under reduced-motion/data-saving preferences. Captions and credits remain visible. Escape/Close returns focus to the opener.
- Website settings → Branding: upload light/dark replacement logos and an optional browser icon. Leaving these empty preserves the original identity. Light/dark artwork is selected automatically for the header/footer; the About mark uses the same settings. The icon is now a public asset rather than a higher-priority Next file icon, allowing the CMS override to work.
- Download original vector and transparent PNG logo/symbol variants at `/brand/`, also linked from the footer and Getting started. These use the original DA paths and outlined OFL Manrope lettering. Source SVGs and PNGs are included; `scripts/export-brand.py` is an optional local authoring tool requiring fontTools and Brotli, not a production dependency.
- Website settings → Labels: edit navigation, hero/project calls to action and the footer note. Anchors remain stable when labels change.
- Website settings → SEO and each project's Search & sharing group: edit search titles, descriptions and sharing images. Existing documents use defaults without migration or overwrite.
- Public contact links use the configured email, if any, and the approved studio Instagram profile. Email links open the visitor's email application with encoded project context; they do not claim a message has been sent. The old demonstration form and unused delivery helper are removed. No paid form provider was added.
- `/privacy/` explains the display preference in localStorage, public media requests, Netlify/Sanity hosting and separate editor authentication. The owner still needs to confirm provider retention and internal enquiry-handling arrangements. No analytics or advertising integration was added, so no speculative consent banner was introduced.

## Security and dependencies

Next.js and eslint-config-next are updated to 16.4.6; Sanity to 6.24.0. Compatible patched overrides update old js-yaml, smol-toml and minimatch dependencies. The public app's production audit has no reported findings at this check. Its development-tool audit retains affected packages from the same unpatched picomatch advisory; patched minimatch overrides also apply to the root workspace. The editor's production dependency audit retains 23 high-severity affected-package entries, cascading from the picomatch repeated-extglob ReDoS advisory (GHSA-fc5q-39xc-vjpf). The newest available picomatch checked is 4.0.7 and is still affected. No force downgrade or unverified replacement is applied.

Affected paths are under Sanity/CLI globbing and build-tool dependency chains. The public static portfolio does not accept glob expressions. This review does not establish that every affected editor dependency is unreachable in every scenario; do not describe the editor as fully security-cleared. Keep untrusted source/configuration and arbitrary glob expressions out of build inputs, monitor the upstream fix and update when available.

The full Netlify build generates per-route CSP headers using hashes of the actual inline Next scripts. The editor has a separate policy for Sanity authentication/CDN connections. Script unsafe-inline and unsafe-eval are not enabled; inline styles remain allowed for React styles and Studio's styling system. Frame embedding is denied, MIME sniffing is disabled and HTTPS/referrer/feature policies are set. The local export server emulates the response headers for browser verification. These are deployment controls, not a claim of a complete penetration test or legal compliance.
